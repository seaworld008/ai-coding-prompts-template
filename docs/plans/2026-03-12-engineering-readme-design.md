# Engineering README Design

## 背景

当前仓库的 README 已经有不错的导航能力，但仍然更像“文档索引页”，还不够像一个成熟开源仓库的工程 README。

主要不足：

- “这是什么”与“为什么存在”还可以更聚焦
- 缺少明确的“如何使用 / 如何开始”
- 缺少前置条件与配置说明
- 缺少真实使用示例
- 缺少限制与适用边界说明

## 目标

把 README 升级成一份高质量工程 README：

- 清晰
- 简洁
- 实用
- 面向真实用户和维护者

## 方案对比

### 方案一：保留现有结构，只补几个段落

优点：

- 改动小
- 风险低

缺点：

- 首页整体信息架构不会明显变好

### 方案二：重构 README 成工程 README

优点：

- 能完整回答用户最关心的问题
- 更适合 GitHub 首页阅读
- 仍然保留现有导航能力

缺点：

- 需要重排现有章节

### 方案三：把 README 做成文档目录 + 长篇说明混合体

优点：

- 信息更全

缺点：

- 首页容易过长
- 首次阅读成本高

## 推荐方案

采用方案二。

## 设计原则

- 首屏先回答“是什么、为什么存在、怎么开始”
- 中部提供“安装 / 使用 / 示例 / 专题入口”
- 后部提供“限制、贡献、维护、支持”
- 保持中文主叙事，保留必要英文一句话说明
- 避免空泛宣传式措辞
