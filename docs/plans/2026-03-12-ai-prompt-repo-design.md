# AI Prompt Template Repository Design

## 背景

当前项目只有一份总清单文档，内容质量已经不错，但不适合直接作为开源 GitHub 仓库维护。主要问题是：

- 入口单一，无法快速跳转到具体专题
- 后续扩展会持续堆在一个文件里，维护成本高
- 缺少开源仓库常见的基础文件和结构

## 目标

把现有清单整理成一个适合开源的 GitHub 样板仓库，同时继续扩展以下专题版本：

- Kubernetes 专用版
- Nginx 专用版
- Shell / Bash 专用版
- Python 自动化专用版
- Windows Server 自动化专用版
- OpenClaw / Codex / Claude Code 专用版

## 方案对比

### 方案一：继续维护单文件

优点：

- 改动最少
- 迁移最快

缺点：

- GitHub 浏览体验差
- 难以做专题导航
- 长期维护和协作不友好

### 方案二：README 总览 + docs 分专题

优点：

- 最适合 GitHub 开源仓库
- 首页可做快速导航
- 专题内容独立，便于持续扩展
- 保持 Markdown 风格统一，不需要额外工具链

缺点：

- 初次整理需要补一轮目录结构

### 方案三：文档站点化

优点：

- 展示能力最强
- 后续检索体验好

缺点：

- 超出当前“先做成可开源模板仓库”的必要范围
- 增加构建和部署复杂度

## 推荐方案

采用“README 总览 + docs 分专题”的结构，优先完成仓库化和内容扩展，暂不引入文档站点框架。

## 信息架构

### 根目录

- `README.md`
- `LICENSE`
- `.gitignore`
- `CONTRIBUTING.md`
- `docs/`

### docs 目录

- `docs/general/`：通用清单和组合模板
- `docs/specialized/`：专用版专题文档
- `docs/plans/`：设计与实施文档

## 文档策略

### README

README 负责：

- 说明仓库定位
- 提供快速导航
- 解释如何使用提示词
- 列出通用版和专用版入口
- 说明贡献方式

### 通用文档

保留一份整理后的主清单，作为 README 之外的完整总览文档。

### 专题文档

每个专题文档都沿用当前 Markdown 风格：

- 标题清晰
- 中文说明 + 英文提示词
- 可直接复制使用
- 结构尽量一致

## 扩展内容原则

- 保持“提示词英文、说明中文”的格式不变
- 每个专题文档独立成篇，避免 README 过长
- 专题尽量覆盖真实工程使用场景，而不是泛泛表述
- 通用版与专用版之间避免大量重复

## 非目标

- 暂不引入静态站点生成器
- 暂不拆成多语言版本
- 暂不增加复杂自动化脚本

## 交付结果

本次整理完成后，仓库应至少包含：

- 一个可直接开源的 README
- 一份整理后的通用总清单
- 六份新增专用版文档
- 基础开源仓库文件

## 风险与处理

- 原始内容较长：通过 README 导航和专题拆分解决
- 专题风格漂移：统一采用当前文档的写法
- 未来扩展混乱：预留 `docs/specialized/` 作为固定扩展区
