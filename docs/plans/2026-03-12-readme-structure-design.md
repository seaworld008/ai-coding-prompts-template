# README Structure Redesign

## 背景

当前 README 的信息已经比较完整，但存在两个典型问题：

- 首页内容较多，信息层级不够聚焦
- “怎么选、怎么用、去哪里看”的路径可以更顺

这会导致首次进入仓库的用户需要往下读较长内容，才能建立清晰的阅读路径。

## 目标

把 README 重排成更清晰的工程首页结构，让用户可以更快完成下面三件事：

1. 判断这个仓库是不是自己需要的
2. 快速找到合适的提示词入口
3. 立即开始使用

## 方案对比

### 方案一：只调整个别章节位置

优点：

- 改动最小
- 风险低

缺点：

- 首页整体逻辑提升有限

### 方案二：工程 README 重排

结构改为：

- 概览
- 选择
- 上手
- 示例
- 导航
- 维护与协作

优点：

- 逻辑最顺
- 更适合 GitHub 首页阅读
- 不需要删除已有信息

缺点：

- 需要重排现有章节

### 方案三：极简首页 + 全部跳转 docs

优点：

- 首页更短

缺点：

- 用户需要频繁跳转
- 不够像高质量工程 README

## 推荐方案

采用方案二。

## 最终结构

- 标题 + 一句话定位
- 这是什么
- 为什么存在
- 适合谁用
- 按任务选择指南
- 快速开始
- 常见使用示例
- 内容导航
- 安装与获取
- 前置条件
- 仓库结构
- 维护约定
- 限制与注意事项
- 贡献与协作
- 开源说明
- 设计记录

## 设计原则

- 前半部分优先服务首次访问者
- 中间部分优先服务立即使用
- 后半部分优先服务维护者和贡献者
- 保持当前 Markdown 风格简洁直给
